# 部署说明（照抄即可，5 步）

目标：装完之后，手机浏览器打开 `http://<你电脑IP>:3090/rc`，直接进 ZCode 远程页 ——
免登录、iOS 16.3 也能开、顶栏不压状态栏、输入框不被屏底裁掉。

> 这套东西**不改 ZCode 一个字**。ZCode 保持官方原版，网关只在旁边做改写和中继。

---

## 第 0 步 · 先确认三件事

| 项 | 要求 | 怎么查 |
|---|---|---|
| ZCode 桌面端 | 官方原版，已登录，能打开「远程控制」 | 打开 ZCode 看一眼即可 |
| Node.js | **20 或更高** | `node -v` |
| 电脑和手机 | 同一个 WiFi / 同一局域网 | 手机浏览器能开 `http://<你电脑IP>:3090/diag` 就算通 |

查自己的局域网 IP：

```powershell
ipconfig | findstr /i "IPv4"
```

取 `192.168.x.x` 那一条（不要用 127.0.0.1，也不要用手机会话里的 `172.x`）。

---

## 第 1 步 · 放文件（目录结构必须是这样）

```
D:\zcode-rc\zcode-rc-gateway\
├─ runner.mjs          ← 主程序，启动这个
├─ mobilefix.js        ← 手机端适配补丁
├─ diag.html           ← 自检页，打不开时先开它
└─ lib\
   └─ proxy.mjs        ← 改写管线（1.4 MB，必须是本包这份）
```

四个文件都在本包里，直接整目录复制过去即可。
**`lib\proxy.mjs` 不能换成别处的版本** —— 官方安装包里的原版没有 ZCode 改造，iOS 16.3 会卡在黑底 Z 启动壳。

`runner.mjs` 会自动按自身位置推导路径，不需要改任何一行代码。

---

## 第 2 步 · 让 ZCode 的二维码指向你自己的网关

```powershell
setx ZCODE_WEB_REMOTE_CONTROL_URL "http://192.168.1.23:3090/remote/v4"
```

把 `192.168.1.23` 换成第 0 步查到的**你自己的 IP**（端口 `3090` 不要改）。

**设完必须完全退出 ZCode 再重开**（托盘图标右键退出，不是关窗口）。
这一步不做，ZCode 生成的二维码仍然指向官方地址，扫了照样走官方、照样在 iOS 16.3 卡住。

---

## 第 3 步 · 启动网关

先手工跑一次，看到 `listening 0.0.0.0:3090` 就成功：

```powershell
cd D:\zcode-rc\zcode-rc-gateway
node runner.mjs
```

正常输出会同时监听 `3090`、`3091`、`80` 三个端口（换源站用，任一条都能开）。
其中 `80` 被占用会打 `startup failed on :80`，**不影响使用**，3090 照常工作。

确认开机自启（可选，但强烈建议）：

```powershell
node install.mjs --target D:\zcode-rc\zcode-rc-gateway --task --port 3090
```

它会注册计划任务 `ZcodeRcGateway-3090`（隐藏窗口、开机自启）并立刻启动一次。

---

## 第 4 步 · 放行防火墙（否则手机连不上）

```powershell
New-NetFirewallRule -DisplayName "zcode-rc-gateway" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3090,3091,80 -Profile Private
```

只需要 `Private`（家庭/办公网络）。**不要**做公网端口映射。

---

## 第 5 步 · 配对一次，然后手机开 /rc

这一步**顺序不能颠倒**，颠倒就会「页面能开但一直转圈」。

1. 电脑上打开 ZCode → 远程控制 → **生成二维码**
2. 手机**扫一次**这个二维码。因为第 2 步设过环境变量，二维码里的地址已经是
   `http://<你电脑IP>:3090/remote/v4?sid=…&mid=…`，打开后页面会自己把这对参数记到网关的
   `last-pair.json` 里 —— 这一步只做一次。
3. **扫码那次打开的页面不要存书签。** 它带的是当次的一次性 `mid`，存下来以后迟早失效。
4. 之后手机固定用这个短地址，不用再扫、不用再改：

```
http://<你电脑IP>:3090/rc
```

`/rc` 每次都从 `last-pair.json` 现取最新 sid + mid 并拼一个全新的时间戳，
所以桌面端重启、换二维码、sid 变了，它都自动跟上。

> 怎么确认配对已经记住：电脑上跑
> `curl -s http://127.0.0.1:3090/rc -o NUL -D - | findstr location`
> 出来的 `location` 里 `mid=` 后面**不是空的**，就说明记好了。
> 如果 `mid=` 是空的，说明还没扫码，回第 1 步。
>
> 手机上也有同样的提示：没配对时打开 `/rc`，网关会把你送到 `/diag` 页，页面顶部一条红字
> 「还没配对（缺 mid）」——看到这条就是没扫码，不是网络问题。

---

## 怎么判断成功

电脑上跑这两条，都应答对：

```powershell
# 1) /rc 应该是 302，且 location 带 _zcrc=毫秒戳
curl -sI http://127.0.0.1:3090/rc | findstr /i "HTTP location"

# 2) 正式页应该是 200
curl -s -o NUL -w "%{http_code}`n" http://127.0.0.1:3090/rc -L
```

手机上打开 `http://<你电脑IP>:3090/diag`，页面会逐项打勾（安全区、垫片、缓存头、隧道）。
全绿再用 `/rc`。

---

## 故障对照（按现象查）

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机打不开，电脑本机能开 | 防火墙没放行 | 回第 4 步 |
| 卡在黑底 Z 启动壳不动 | `lib\proxy.mjs` 不是本包这份 | 用本包覆盖，重启网关 |
| 一直转圈 / 连不上中继 | 没扫码，或扫的是旧二维码 | ZCode 重新生成二维码，手机重扫 |
| 打开还是官方登录页 | `ZCODE_WEB_REMOTE_CONTROL_URL` 没设或没重启 ZCode | 回第 2 步，确认托盘退出后重开 |
| 顶栏压着状态栏 / 输入框贴屏底 | `mobilefix.js` 没加载 | 确认文件在网关目录里，重启网关 |
| 昨天能开，今天又卡住 | 用的是带 `sid=` 的旧地址 | 改回 `/rc`，它会自动补最新参数 |
| `:3090` 起不来 | 端口被别的程序占了 | `netstat -ano | findstr :3090` 查占用，或改 `ZCODE_RC_PORT` |

---

## 三条红线

1. **只在可信内网用**。网关本身零鉴权，同一 WiFi 谁都能开，**绝不做公网端口映射**。
2. **ZCode 保持官方原版**。改了它连不上官方中继。
3. **`last-pair.json` 不随包分发**。本包不含它，配对信息各自扫码生成，互不干扰。
